> 审查范围：481 个 Kotlin 文件 / 171,710 行（主源码），重点深审近期阶段 4.12~5 与 UI A+B 改动，全库静态扫雷。

## 一、总体结论

**架构严谨度：高。** 无 GlobalScope 滥用（仅 2 处 OAuth 回调场景，属合理越界且内部有 try/catch 兜底）、无 `!!` 空断言、异常处理成体系（runCatching 339 处多为边界防御 + 日志，非静默吞）、DB 迁移幂等、prompt 缓存友好的字节稳定布局有注释护住。

**功能搭配：静态核对全部打通。** 交互矩阵见 §三。

**发现并修复（本次 commit）**：P2 × 3（见 §二）。

## 三、功能搭配矩阵（静态核对）

| 交互链 | 结论 |
|---|---|
| dropbox 热加载 → 技能 prompt 注入 | ✅ processDropzone 在 buildSystemPrompt 顶部、reloadFromDisk 之前，同一轮即可见 |
| dropzone 通知 → 聊天流 | ✅ runAgentLoop 入口 flush，位于任何流式内容之前（本次修复覆盖竞态） |
| lessons 采集 → 提炼 → 注入 | ✅ agent loop 内采集、循环尾 record、下轮 system prompt 注入（memoryOn 门控与 memory 语义一致） |
| lessons ↔ compact | ✅ lessons 在 system prompt 不在 history，压缩不触碰 |
| lessons ↔ branching/cross-validation | ✅ 共享 buildSystemPrompt，交叉验证分支同样受益（符合意图） |
| dropzone × session_skill_overrides | ✅ 导入走 insertDb（IMPORT OR REPLACE），enabled 默认开，overrides 表按 skill_id 关联不受影响 |
